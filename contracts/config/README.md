# Installed webhook configuration v1

The local MVP contracts were adopted on 2026-10-13. This installed increment
supports webhook-only `config validate`; SMTP/mixed configuration validation
returns an explicit unavailable diagnostic before looking up resources.

`webhook-v1.schema.json` describes structural shape. It is not sufficient on its
own: Rust also rejects duplicate decoded keys, non-integer numeric lexemes,
unknown keys, more than 65,536 bytes, depth above eight, object/array budgets,
invalid route references/duplicates, seed overflow and operational cross-field
relationships. Files require an absolute non-symlink path, owned regular config
with mode 0600 in an owned mode 0700 parent and safe ancestors. The loader bounds
reads and rejects concurrent metadata changes. No config/state path discovery.

All webhook URL/auth environment references are checked without sending. URLs
must be bounded printable ASCII, HTTPS, with a host, no userinfo or fragment.
Authorization values are bounded printable ASCII. Neither resource values nor
private paths are emitted. Missing/unusable resources exit 2. Successful output
contains only schema version, safe cluster alias, provider count and SMTP
permission applicability. Validation creates no state and executes no scheduler.
OS environment lookup allocates before the accepted-byte bound; no hard startup
lookup deadline is claimed. Proxy and custom-CA behavior remain unsupported.

The example is synthetic: its numbers are explicit examples, not implicit defaults
or a polling-policy recommendation. Set real environment references only after
choosing an authorized destination and confirming cluster policy for monitoring.

Compatibility: this adds a command and expands global help in the unreleased
0.0.0 development package. Version output and existing error/no-argument streams
remain stable. Baselines are intentional and never regenerated by tests.
